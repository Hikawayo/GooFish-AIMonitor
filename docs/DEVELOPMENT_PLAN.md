# GooFish-AIMonitor：市场监控三阶段计划

> 基于 [tristanwqy/GooFish-AIMonitor](https://github.com/tristanwqy/GooFish-AIMonitor) Fork。目标是复用现成闲鱼采集能力，先完成 Live 票务价格监控，再扩展到其他商品。这里是**计划**，不是已实现功能。

**实时开发状态与 AI 接力入口**：[PROGRESS.md](PROGRESS.md)。本文件仅存需求与阶段验收；开发时持续更新进度快照，避免下一位 AI 重扫项目。

## 开发原则

- **Avoid unnecessary secondary labels and descriptions. Let the layout do the explaining.** 页面靠布局、信息层级和操作位置表达含义，不堆叠解释文字、重复标签和状态徽章。
- **不写只是为了防止被质疑的代码。** 优先最直接、容易理解的实现；不为未发生的假想场景提前加抽象层、兼容逻辑和冗余兜底。
- **不做只是为了防止被质疑的测试。** 只验证真实关键行为和已遇到的缺陷，不为凑覆盖率、装饰交付材料或回应假想质疑写测试；但数据准确性、权限隔离、部署安全等必要验证不能省略。
- 先复用，再修改，最后新增；少量清晰模块胜过完整重构。
- 关键词、目标价格、模型配置、抓取频率等都在配置或网页设置中管理，不把个人 Live 信息写死进业务代码。
- 无需独立用户系统、复杂角色矩阵、消息队列、微服务、模型训练或交易自动化。

## 项目用途与最小闭环

**主要场景**：监控 2027-01-11「millsage × 一家Dumb Rock! SPECIAL LIVE」，对照 2027-01-09 Morfonica，后续可增删其他 Live 或普通商品监控组。

最小闭环：**搜索 → DeepSeek 判断是否属于目标 → 存入监控组 → 网页查看 → 价格变化记录 → 低价提醒**。

需要区分：
- **挂牌价**不等于成交价；「已出」、下架、搜索消失不自动判定已按该价格成交。
- 同一商品 ID 多关键词命中只算一条；同一商品可能捆绑不同演出。
- 全市场行情采集**不按预算价格截断**；¥1,000 理想价、¥1,100 接受价只是可配置提醒门槛。
- 实际监控对象是「系统发现并能访问的商品」，不是承诺闲鱼全站零遗漏。

## 阶段二：监控分组、公开可见性和多用户隔离

**目标**：票务和普通商品各自归档。用户可为自己的监控选择公开或私密。复用现有 SSO，维持单实例部署。

- [x] 推荐页进入后，右侧按监控条件显示文件夹，窄屏使用可展开的选择器。条件支持按公开或私密筛选。允许把同一演出的多条搜索条件归入同一组，让「对邦」只占一个文件夹。条件改名后历史数据仍归原组。（已上线）
- [x] 收藏页沿用监控组和可见性筛选，仅显示当前用户收藏。公开组分享商品与行情，个人收藏、忽略、私有审核记录和备注归当前用户。来源于公开组的个人收藏仍是私密的。（已上线）
- [x] 推荐、公开行情和收藏支持按价格、发布日期升降序。公开候选和本人列表采用一致的匹配、忽略及状态口径，公共卡片展示挂牌封面和卖家昵称。（已上线）
- [x] Web 收藏默认存入本站。按现有收藏刷新间隔打开到期商品详情复检价格，检查数量设上限，识别失败保留原价。复检阶段不重新搜索或调用 AI。（已上线，复检见 refresh_local_favorites）

- [x] 账号可以只绑自己的闲鱼账号、不绑 AI API：关闭「AI 审核」后搜索照常运行，候选不带 AI 裁决进入待审队列，由本人逐个通过或忽略；人工通过/忽略写入该条件的匹配记录，公开行情据此判断已确认匹配。不调用模型，也不产生接口费用。
- [x] 每个商品在卡片上直接打开展示最近挂牌价、记录最低、价格走势图和逐条观测时间，不必为看趋势先跳去闲鱼商品页。
- [x] 单个条件内的价格总览：把该条件下所有商品画进同一张走势图（每件商品细线 + 最低价 + 中位数），时间轴从最早观测到最近刷新自适应，支持 全部时间 / 按天 / 按周 / 按月 切换，悬停可读具体时间与价格。
- [x] 主题只保留浅色（白 + `#00AABB`，新用户默认）与深色（黑白）两套预设；顶栏色板末尾提供「＋」，用背景/文字/强调三个颜色自定义主题，改色即时预览，保存后只对该浏览器生效。
- [x] 首次进入弹出公告（使用说明 + 更新日志两页），关闭后从顶栏主题左侧的入口可再打开；公告内容按版本号记忆，改版后老用户会再看一次。
- [x] 新人第一次打开站点不该看到空页：没有自己的条件时直接落到公开组；收藏页默认落在真有收藏的文件夹；每个文件夹标出条数，避免侧栏总数与列表中数量对不上。
- [x] 卡片信息按决策价值分层：卖家（谁在卖）用首字母圆点和正常文字色排在行首，包邮徽标紧随，地区/成色留作弱色；行内元素基线/中心线对齐，中文与数字混排不错位；全局字体统一微软雅黑。

- [x] 按组与商品 ID 唯一关联。同一商品允许命中多组，同一组中多关键词命中去重。价格观测按组留存，公开组不能通过同一商品 ID 带出其他组的私密结果。（WatchMatch / PublishedPrice 按条件留存）

## 阶段二·五：敢推荐给朋友（可靠性收口）

**目标**：朋友第一次打开就能跑通「看公开组 → 扫码 → 建条件 → 自动抓取 → 收藏 → 降价提醒」，每种失败都有看得懂的提示，不再出现「看着正常、其实没在跑」。**做完这一段之前，不推进阶段二剩余功能和阶段三。**

来源：2026-11-24 快速体检。三路只读审查（新成员路径、前端可靠性、后端数据），当时 verify 全部通过。下面的行号对应当时的版本，动手前先用 grep 重新定位。

### 验收

找一个从没用过本站的 SSO 账号，在手机上从零走一遍：首屏看到公开组 → 扫码 → 建条件 → 不手动点，一个周期内也会自动抓取 → 人工通过 → 收藏 → 降价出现在事件里。走的同时，让管理员在跑抓取、另一个人在扫码，三个人都不能出现「被跳过」。中途分别让 SSO 过期、闲鱼登录过期、断网各一次，每种情况都要有看得懂的提示。

## 阶段三：中重度开发（持续追踪与市场分析）

**目标：自动看到「哪些卖家在降价、市场价格有没有整体回落」，支持跨 Live 比较。只做有用的分析。**

- [x] 对已跟踪的商品建立定时复查（`refresh_local_favorites` + 详情核活），不依赖是否仍在搜索页或闲鱼收藏夹。
- [x] 记录每次有效观测：商品 ID、价格、时间、来源、状态；抓取失败保留原价不误判，已下架商品重新在搜索中出现时自动恢复在售（`repo.revive_item`）。
- [x] 让 DeepSeek 在**首次出现或文本变化**时识别席种（内场/看台/未知）、票数、捆绑、定金、单张/合计价；不反复对已有属性的商品调用模型。
- [x] 在可比较的普通单票挂牌中计算最低价、中位数、P25、在售数量、降价/涨价数量；捆绑票、定金或合计价单独排除，不混入价格统计。

- [x] 可选 DeepSeek 简短日报（`digest.py` + `POST /api/digest`）：SQL 先统计，模型只概括趋势和不确定性，未配模型时回退纯统计摘要。

## 网页访问方案：回答「同事能不能一起看」

**可以，原项目已经是网页应用**：React 前端 + FastAPI API，Docker 默认绑定 `127.0.0.1:8000`。

- **阶段一**：你自己访问原有后台，完成部署和数据验证。浏览器可用，但不等于可安全公开。
- **阶段二**：同事通过 SSO 查看公开组；自行采集、审核和收藏需配置自己的闲鱼账号与模型接口，且只能修改自己的数据。站点管理权限独立。
- **阶段三**：共享页继续提供历史曲线和多组对照。

**最小安全要求**：后台管理/API不得无认证公开在互联网；只读限制必须落实到服务端；敏感信息不传给访客；建议先采用私有网络或现成代理认证，避免自行开发复杂登录系统。

## 本次采用的源码事实与边界

- `search.py`：搜索结果包括 ID、标题、价格等；每个 `Watch` 的词块拼为**一条**搜索查询。
- `review.py`：已支持兼容 Chat Completions 的 AI 审核；当前仅按标题等概要判断，失败会放行，要改变这一语义。
- `service.py`：已推荐过的商品会跳过后续推荐；阶段二需让重复搜索仍更新价格观测。
- `pipeline.py` / `favorites_list.py`：持续降价监控现阶段主要依赖闲鱼收藏夹。
- `storage/orm.py`：已有 `items`、`price_history` 和 `events`，不必另建整套数据库。
- `web/app.py`：已有管理 API、前端托管及扫码登录接口；**没有现成的完整只读权限隔离**。

参照上游 [README.md](https://github.com/tristanwqy/GooFish-AIMonitor/blob/main/README.md)、[AGENTS.md](https://github.com/tristanwqy/GooFish-AIMonitor/blob/main/AGENTS.md) 和上述源码。实际能否在腾讯云稳定登录、采集，仍需阶段一实测。

## 实施顺序

1. 先跑通原功能并确认云服务器可用。
2. 先做稳定文件夹、记录归属和服务端权限，再接入第二个 SSO 用户验收独立采集与共享。保持 DeepSeek 识别和价格观测按组工作。
3. 先完成「阶段二·五」的 P0、P1 并通过验收，再做阶段二剩余项（目标价提醒优先）。
4. 再做「固定商品复查 + 历史图 + 市场分析」。
