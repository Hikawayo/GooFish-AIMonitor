# GooFish-AIMonitor：市场监控三阶段计划

> 基于 [tristanwqy/GooFish-AIMonitor](https://github.com/tristanwqy/GooFish-AIMonitor) Fork。目标是复用现成闲鱼采集能力，先完成 Live 票务价格监控，再扩展到其他商品。这里是**计划**，不是已实现功能。

## 开发原则

- **Avoid unnecessary secondary labels and descriptions. Let the layout do the explaining.** 页面靠布局、信息层级和操作位置表达含义，不堆叠解释文字、重复标签和状态徽章。
- **不写只是为了防止被质疑的代码。** 优先最直接、容易理解的实现；不为未发生的假想场景提前加抽象层、兼容逻辑和冗余兜底。
- **不做只是为了防止被质疑的测试。** 只验证真实关键行为和已遇到的缺陷，不为凑覆盖率、装饰交付材料或回应假想质疑写测试；但数据准确性、权限隔离、部署安全等必要验证不能省略。
- 先复用，再修改，最后新增；少量清晰模块胜过完整重构。
- 关键词、目标价格、模型配置、抓取频率等都在配置或网页设置中管理，不把个人 Live 信息写死进业务代码。
- 无需独立用户系统、复杂角色矩阵、消息队列、微服务、模型训练或交易自动化。

## 项目用途与最小闭环

**主要场景**：监控 2027-01-11「millsage × 一家Dumb Rock! SPECIAL LIVE」，对照 2027-01-09 Morfonica，后续可增删其他 Live 或普通商品监控组。

最小闭环：**搜索 → DeepSeek 判断是否属于目标 → 存入监控组 → 网页查看 → 价格变化记录 → 低价提醒**。

需要区分：
- **挂牌价**不等于成交价；「已出」、下架、搜索消失不自动判定已按该价格成交。
- 同一商品 ID 多关键词命中只算一条；同一商品可能捆绑不同演出。
- 全市场行情采集**不按预算价格截断**；¥1,000 理想价、¥1,100 接受价只是可配置提醒门槛。
- 实际监控对象是「系统发现并能访问的商品」，不是承诺闲鱼全站零遗漏。

## 阶段一：立马能用（部署上游原有功能）

**目标：先在腾讯云 Ubuntu 上看到真正的搜索结果和现成 Web 页面；不修改业务代码。**

- [ ] 部署原仓库 Docker Compose，确认容器运行、SQLite 数据保存在 `./data`，重启不丢数据。
- [ ] 通过现成 Web 控制台扫码登录闲鱼，验证至少一组真实关键词可以获得商品标题、价格、商品链接。
- [ ] 在网页创建几个独立搜索条件：完整 Live 名、简称/别名、日期组合；原项目一条监控条件中的 `keywords` 是拼成**一次搜索**，不是多关键词 OR 搜索。
- [ ] 配置现有 OpenAI 兼容模型接口到 DeepSeek，验证审核结果及失败提示；API Key 只放受保护配置，不提交 GitHub。
- [ ] 查看新推荐、手动收藏后降价、基础事件与现成邮件通知，确认它们的实际效果。
- [ ] 验证网页在电脑和手机浏览器能打开；管理员先通过 SSH 隧道或私有网络访问，**暂不把现有后台直接公开给同事**。
- [ ] 做必要的真实验收：登录、搜索、AI判定、持久化、通知。记录不能获取数据、账号验证等实际阻塞，不盲目高频重试。

**可直接复用的源码**：`search.py`、`review.py`、`service.py`、`pipeline.py`、`storage/`、`web/app.py`、`web/scheduler.py`、`frontend/src/`、`Dockerfile`。

**阶段完成标准**：腾讯云的网页能看到新上架候选及AI结果，能通过收藏夹观察降价。此时**还不能**声称已经监控所有未收藏商品的价格变化。

## 阶段二：轻度修改（识别、分组、共享网页）

**目标：让它成为「自己的监控系统」，别人也能安全查看当前结果。保持简单。**

- [ ] 增加「监控组」：名称、类型（`live` / `general`）、搜索词数组、目标价格、启用状态；Live 组可选日期、场馆、别名。不同词对应独立查询，结果统一按商品 ID 去重。
- [ ] 利用现有 `review.py` 接 DeepSeek 判断是否属于目标；特别排除不同日期的同团 Live、各自1st、同名无关商品。结果只需要 `matched / rejected / uncertain` 和一句简短理由。
- [ ] AI 接口失败或证据不足归为「待确认」，不要沿用原项目失败即放行的结果作为确认命中。支持手动改正归属；结果保存在数据库，同一文本不重复请求 DeepSeek。
- [ ] AI确认命中的商品自动加入**本地跟踪数据库**，不需要自动点击闲鱼收藏。可手动粘贴商品 URL/ID 加入监控。
- [ ] 搜索再次发现同一商品时，更新最新价格和观察时间，而不是因为「已推荐」跳过；沿用已有 `price_history`。
- [ ] 新增目标价提醒：新商品价格 ≤ 设定值、旧商品下调至目标价；事件去重，先沿用邮件通知。
- [ ] 基于现有 React + FastAPI 做**只读行情页面**：监控组选择、目前最低挂牌、在售商品列表、价格、最近观测时间、商品链接。优先保证手机可读，少标签少说明。
- [ ] 同事可通过浏览器访问只读页面；管理员操作与只读访问隔离，采用简单的反向代理身份验证或可信私有网络。**不能只在前端隐藏按钮，服务端也必须限制写接口。**
- [ ] 保留原项目通用商品搜索/收藏功能，不将页面和数据结构绑定到这两场演出。
- [ ] 只检查关键行为：AI错场过滤、重复ID、旧商品变价、低价提醒、访客无法写入。前端实际操作可用即可。

**主要修改**：`service.py`、`review.py`、`storage/orm.py` / `repo.py` / `migrate.py`、`web/app.py` / `dto.py`、`frontend/src/sections/`；尽量不动底层登录与网页采集实现。

**阶段完成标准**：你和同事可以在手机/电脑网页查看同一监控组的最新挂牌。DeepSeek新票判定入库，搜索重复观测能记录价格变化，并能收到低价提醒。**搜索暂时不返回的旧商品不保证连续更新。**

## 阶段三：中重度开发（持续追踪与市场分析）

**目标：自动看到「哪些卖家在降价、市场价格有没有整体回落」，支持跨 Live 比较。只做有用的分析。**

- [ ] 对已跟踪的商品建立定时复查，不依赖是否仍在搜索页或闲鱼收藏夹；沿用现有详情访问能力，核实能否从详情接口读取当前价、描述和状态。
- [ ] 记录每次有效观测：商品 ID、价格、时间、来源、状态。抓取失败记「未知」，不当作下架/成交；可以恢复已下架后重新出现的商品。
- [ ] 让 DeepSeek 在**首次出现或文本变化**时识别席种（内场/看台/未知）、票数、母子票、连番、捆绑、单张/合计价、风险条件；不确定就留空/待人工确认，不反复对未变的商品调用模型。
- [ ] 在可比较的普通单票挂牌中计算最低价、中位数、P25、在售数量、新增/降价/涨价数量；捆绑票、只报订金或单位不明的票单独展示，不混入价格统计。
- [ ] 增加走势图和商品价格历史，支持按监控组/席种/时间筛选；可比较 Morfonica 与新团对邦，但不把挂牌下架认定为成交。
- [ ] 可选 DeepSeek 简短日报：SQL先统计，模型只概括趋势和不确定性，不让模型编造市场交易量或预测百分比。
- [ ] 共享只读页面展示趋势与历史；结束的监控组可归档查看，普通商品也能复用追踪器。保持 SQLite 单实例，确有性能问题再考虑更复杂方案。
- [ ] 运行稳定性：适度扫描、限量和失败暂停，定期备份数据库及配置；验证重启、价格计算、状态误判和只读权限即可，不做形式化的庞大测试矩阵。

**主要开发**：独立 `listing_tracker` 复查流程、详情解析、市场汇总查询、趋势页面，以及必要的数据库字段。保持与上游代码低耦合。

**阶段完成标准**：系统能够持续记录已发现商品的价格变化，在 Web 上展示每场 Live 的价格走势和挂牌结构，并可靠区分「观察到」和「推测」。

## 网页访问方案：回答「同事能不能一起看」

**可以，原项目已经是网页应用**：React 前端 + FastAPI API，Docker 默认绑定 `127.0.0.1:8000`。

- **阶段一**：你自己访问原有后台，完成部署和数据验证。浏览器可用，但不等于可安全公开。
- **阶段二**：新增适合多人共享的只读页面；同事浏览器打开同一个地址查看结果，**不必给他们闲鱼账号或 DeepSeek Key**。管理后台仍只对你开放。
- **阶段三**：同一只读页面扩展历史曲线、多个活动和普通商品监控组。必要时才加账号体系，不预先开发。

**最小安全要求**：后台管理/API不得无认证公开在互联网；只读限制必须落实到服务端；敏感信息不传给访客；建议先采用私有网络或现成代理认证，避免自行开发复杂登录系统。

## 本次采用的源码事实与边界

- `search.py`：搜索结果包括 ID、标题、价格等；每个 `Watch` 的词块拼为**一条**搜索查询。
- `review.py`：已支持兼容 Chat Completions 的 AI 审核；当前仅按标题等概要判断，失败会放行，要改变这一语义。
- `service.py`：已推荐过的商品会跳过后续推荐；阶段二需让重复搜索仍更新价格观测。
- `pipeline.py` / `favorites_list.py`：持续降价监控现阶段主要依赖闲鱼收藏夹。
- `storage/orm.py`：已有 `items`、`price_history` 和 `events`，不必另建整套数据库。
- `web/app.py`：已有管理 API、前端托管及扫码登录接口；**没有现成的完整只读权限隔离**。

参照上游 [README.md](https://github.com/tristanwqy/GooFish-AIMonitor/blob/main/README.md)、[AGENTS.md](https://github.com/tristanwqy/GooFish-AIMonitor/blob/main/AGENTS.md) 和上述源码。实际能否在腾讯云稳定登录、采集，仍需阶段一实测。

## 实施顺序

1. 先跑通原功能并确认云服务器可用。
2. 优先做「监控组 + DeepSeek识别 + 入库 + 共享只读页面」。
3. 再做「固定商品复查 + 历史图 + 市场分析」。

**暂不做**：自动买票、自动私聊、价格操纵、用户等级系统、复杂预测引擎、全站商品爬取、为未来假想情况准备的兼容层。
