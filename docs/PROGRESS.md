## 交接记录的维护规则（每位开发 AI 必须执行）

- **开始新任务时**：更新「当前任务」及阶段；只在真正完成后才标已完成。
- **开发过程中**：遇到会影响下一步的设计变化、失败、阻塞或关键结论，立即更新相关项；普通小改动不必写流水账。
- **完成一个可运行节点或额度将尽/切换 AI 前**：更新完成内容、改动文件/关键函数、真实验证结果（成功/失败/未执行）、遗留问题和下一步**第一件事**，并和代码一起提交到 GitHub。
- **如果工作被中断**：明确记录最后一个确认成功的操作，未完成内容标记为未完成；不要虚构验证或部署状态。
- **需要调整计划时**：同步修改 `DEVELOPMENT_PLAN.md` 对应清单；本文件只保留当前状态，不复制整份任务列表。
- **保持精简**：只保留最新进度、必要的阻塞与关键决策。详细变更用 Git 提交历史追溯；不额外建每日流水账、冗余状态表。
- **提交约定**：用户已授权持续维护并提交开发进展；与获授权的业务修改一同提交，必要时单独提交进度文档。不要把未获得授权的功能开发理解为已获授权。
