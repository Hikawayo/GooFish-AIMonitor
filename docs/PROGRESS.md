## 下一位开发 AI 直接从这里继续

1. 使用已登录的腾讯云网页终端或已有授权的 SSH 会话进入目标 Ubuntu，检查 Docker Compose、磁盘、内存、运行中的容器和端口。以 `ss -H -ltn 'sport = :18080'` 检查候选端口；若有占用，另选空闲端口。确认 `xianyu-console` 容器名没有冲突。
2. 将 GitHub `main` 检出到 `/srv/GooFish-AIMonitor`。如该目录已存在，先确认是同一仓库并检查本地改动。创建可持久化的 `data/`，缺少 `data/secret.env` 时以权限 `0600` 创建空文件。将选定端口写到仓库根目录 gitignored 的 `.env`，例如 `GOOFISH_WEB_PORT=18080`，保留已有配置。
3. 运行 `sudo docker compose config --quiet` 再执行 `sudo docker compose up -d --build`，用 `sudo docker compose ps` 核对端口绑定，用 `curl -fsS http://127.0.0.1:18080/` 与 `curl -fsS http://127.0.0.1:18080/api/status` 验证前端和 API，确认 `./data` 的 SQLite 文件及重启持久化。
4. 通过 SSH 本地端口转发打开管理页，完成扫码、真实搜索及 DeepSeek 验证后更新本文件。团队共享留到阶段二的只读页面。

## 交接记录的维护规则（每位开发 AI 必须执行）

- **开始新任务时**：更新「当前任务」及阶段；只在真正完成后才标已完成。
- **开发过程中**：遇到会影响下一步的设计变化、失败、阻塞或关键结论，立即更新相关项；普通小改动不必写流水账。
- **完成一个可运行节点或额度将尽/切换 AI 前**：更新完成内容、改动文件/关键函数、真实验证结果（成功/失败/未执行）、遗留问题和下一步**第一件事**，并和代码一起提交到 GitHub。
- **如果工作被中断**：明确记录最后一个确认成功的操作，未完成内容标记为未完成；不要虚构验证或部署状态。
- **需要调整计划时**：同步修改 `DEVELOPMENT_PLAN.md` 对应清单；本文件只保留当前状态，不复制整份任务列表。
- **保持精简**：只保留最新进度、必要的阻塞与关键决策。详细变更用 Git 提交历史追溯；不额外建每日流水账、冗余状态表。
- **提交约定**：用户已授权持续维护并提交开发进展；与获授权的业务修改一同提交，必要时单独提交进度文档。不要把未获得授权的功能开发理解为已获授权。
