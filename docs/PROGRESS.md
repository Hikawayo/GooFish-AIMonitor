## 2026-11-22 条件内价格总览

- **需求**：降价后要一件件点「价格记录」才知道降没降；需要一个条件内的总览图，把所有商品放进同一张走势图，并按 全部时间 / 按天 / 按周 / 按月 切换。
- **实现**：`trend.py` 负责分桶与聚合（按调用方时区，东八区零点为天/周/月的边界；周从周一起）；`GET /api/price-trend?watch_ids=&mode=&tz=` 返回 `series`（每桶最低价、中位数、在售件数）和 `items`（每件商品自己的点）。前端 `PriceTrend.jsx` 用 SVG 画：每件商品细线 + 最低价实线 + 中位数虚线，悬停读数，粒度切换，收起状态记在 `localStorage`。挂在推荐页和收藏页的当前文件夹上，只对本人条件显示。
- **取舍**：全部时间下时间点按去重后的观测时刻算，超过 240 个就等距抽稀（被抽掉的点并入下一个点，状态不丢）；每个桶取该时段最后一次观测；没在这一刻观测的商品沿用上次价格，所以最低价线不会因为一件商品今天没扫到就断；商品超过 60 件时只画观测最多的 60 条。
- **数据口径（重要）**：只统计「已确认匹配」的商品——`WatchMatch.ok` 不是 `False`，且没被自己忽略（`rec_status != rejected`）。早期版本按「命中过这个条件」全量取数，把 AI 判否的兑换码/特典也画进了走势（线上 28 条），这是错的。
- **纵轴（修）**：即便在已确认的匹配里也可能混进个别低价误判，`trend._auto_floor` 会在商品最新价排序里找最大的「相邻价倍数跳变」（≥6 倍），取两侧几何平均作分界，只保留「历史最高价 ≥ 分界」的商品；没有明显跳变就不动手。
- **范围调节**：不再用输入框和说明文字。图表四条边都能拖：底边上移抬高最低价、顶边下移压低最高价、左右边收窄日期范围；双击图表复位，重新打开/换粒度都回到默认全量。读数跟着可视窗口算「最高 → 现（±%）」。
- **已知语义**：已下架/卖出的商品价格会一直留在曲线上，最低价可能长期被一件已下架商品压住——图中「在售件数」是判断依据，暂不自动剔除。
- **验证**：124 项 pytest（趋势分桶/抽稀/自动分界/跌破下限仍可见/接口校验/AI 判否不入图）；浏览器实测四种粒度、悬停、四边拖拽（上下调价格、左右调日期）、双击复位、重新打开回默认、390px 无溢出。

## 2026-11-22 运行反馈与「搜出来是 0」排查

- **现象**：成员说抓取进行中「立即运行」是灰的、点了没反应；还说怎么搜都是 0。
- **排查**：线上共 1 个成员 scope（`770bd112…`）。他的库里有 **44 条商品、44 条事件、1 条条件**，最近一轮 `2026-11-21 17:14 UTC`（北京时间 01:14），说明搜索一直是成功的；其中 17 条待审、27 条他已自己忽略。他的配置是 `review_enabled=0`（人工审核模式）。
- **「0」的真正来源**：`scan_recommendations` 只把「AI 通过」计为新增，人工审核模式下候选的裁决是 `None`，所以每轮都回「新推荐 0」。他首轮其实收了 44 条，提示却是 0。
- **修复**：
  - 「立即运行」不再 `disabled`：抓取中点击直接 toast「正在抓取中，请稍后再试」，按钮保留变淡的忙碌外观；`/api/run` 在全局浏览器锁忙时回 `409`（而不是静默跳过、假装排上队）。
  - 扫描结果改为 `ScanResult(created, scanned, raw)`，完成提示变成「搜索 N 条 · 命中 M 条 · 新推荐 K 条」，能区分「一条没搜到」「搜到了但被规则挡掉」「搜到了但都不是新的」。
  - 人工审核模式下的新候选计为「新推荐」。
- **日志**：原来 uvicorn 只到 warning，抓取异常只写进内存里的 `last`，重启即丢，线上没有可查痕迹。现在抓取失败、登录失效、无法开始抓取都会打 warning，`docker logs xianyu-console` 可查。
- **「只搜 millsage 是 0」**：他的条件带 `price_min=500`，而 `scan_recommendations` 先按规则过滤再统计，旧版对外只说「新增」——搜索有结果、被价格挡掉、或全是已见过的条目，三种情况都显示 0。现在一轮扫描输出三个数（搜索返回 / 命中规则 / 新入队）并写一行 `INFO` 日志，`docker logs` 里能直接看到是「没搜到」还是「被规则挡掉」。另外 `parse_search_json` 只保留能解析出价格的条目，缺价的结果会被丢弃，这也是数量变少的一个来源。
- **未做的验证**：没有用他的闲鱼登录态在服务器上真跑一次「millsage」搜索（会动用他的账号，需他本人执行）；结论依据是他的库（44 条、最近一轮 01:14）和代码路径，确定答案要他下一轮跑完看提示或日志。
- **验证**：114 项 pytest（新增「搜索有结果但被价格挡掉时 raw>0 / scanned=0」）；用他的库在 390px 复现：17 张卡片正常渲染、忙时点击出 toast、完成提示为「本轮完成：搜索 12 条 · 命中 12 条 · 新推荐 3 条」。

## 2026-11-22 手机点收藏白屏

- **现象**：手机上点「收藏」后整页只剩白底，浏览器标签还在。

## 2026-11-22 卡片排版与字体

- **包邮徽标歪**：`.badge` 自带 `margin-bottom: 9px`，放进 `.rec-meta`（`display:flex` + `align-items:center`）后，居中算法把整个徽标抬起半个外边距，实测比其他文字高约 4.5px。改为徽标本身不带下边距，只有单独占一行的场合（`.rec-body > .badge`）才加，行内中心线对齐到 508.5。
- **时间行歪**：`上架 / 收藏` 是中文、`1 天前 / 11-22` 是数字，原来整行用 `Geist Mono`，中文回退到另一套字体，两套字体的基线不同。统一字体后差值为 0；`.tm-item` 再加 `align-items: baseline`，以后混排也不会错位。
- **信息太平**：卖家原来和地区/成色同一个 11.5px 灰字，用户得在字堆里找。改成首字母圆点 + `--fg` 500 的昵称，排在行首；包邮徽标紧随其后；地区/成色保持弱色。公开卡片同样用这个卖家组件（共享字段本来就只有昵称）。
- **字体**：全局微软雅黑，`index.html` 去掉 Geist/Geist Mono/Noto Sans SC 的外链（少一个 CDN 依赖）。
- **验收**：徽标/卖家/地区中心线一致、时间行标签与数值差 0、390px 无横向溢出；深色与公开卡片截图人工看过。

## 2026-11-22 体验审查

- **并发 500（严重）**：新成员第一次打开页面会并发发 6–8 个请求，每个 `make_session` 都新建 engine 并跑 `create_all`，两个线程同时建表就报 `table items already exists`；`get_config` 同样会撞 `app_config.id` 唯一键。`/api/watches`、`/api/status` 因此 500，前端拿到的是一段 HTML，报「Unexpected token」。修法：engine 按 URL 复用、建表/补列在锁内只做一次；`get_config` 捕获 `IntegrityError` 后重读。新增 6 线程并发首开回归测试。
- **收藏页默认组**：收藏页默认选第一个文件夹「未归档」，而从公开组收藏来的商品挂在公开组里，于是刚收藏完回到收藏页还是「还没有收藏」。改为默认落在真有收藏的组。
- **新成员首屏**：没有任何自己的条件时，首屏是空的「暂无新推荐」，看不出有公开组。没有自己的条件且存在公开组时自动切到「公开」。
- **公开卡片收藏**：点「站内收藏」只弹 toast，按钮文案不变，可以反复点。改为成功后变「已收藏」并禁用（记在本次会话）。
- **计数对不上**：侧栏「推荐 5」是账号总数，列表只显示当前文件夹的 3 条，看着像有商品没加载。文件夹名后补条数（跟随当前「AI 通过/全部」筛选）。
- **标题**：公开视图仍叫「待审推荐」。公开时改为「公开行情」。
- **复核结论**：公开目录不含条件要求文本、私密条件名与审核理由；成员读他人商品的 `/api/items/<id>/prices` 返回 404；成员事件与条件均为 0。

## 2026-11-22 人工审核与价格走势

- **人工审核模式**：`review.ReviewVerdict` 增加 `skipped`；关闭 AI 审核时不再用 `ok=True` 假装通过，改为不留裁决、只进待审队列。`runtime.can_search` 在有登录态时不再强制要求 API Key，`search_block_reason()` 区分「先扫码登录」和「配 Key 或改人工审核」两种提示。`service.record_manual_verdict` 在人工模式下把通过/忽略写入 `WatchMatch`，公开页与 `PublishedPrice` 才认这份确认；AI 模式下该函数直接返回，不动 AI 裁决。
- **走势查看**：`PriceHistory.jsx` 从 `/api/items/{id}/prices` 或公开接口取观测，画线并列出逐条时间与价格；本地收藏由 `refresh_local_favorites` 每轮复检累积观测点，因此几天后打开就有曲线。
- **验收**：种两条测试商品到本地冒烟库（4 个观测点跨 5 天）验证弹窗；线上容器用 `docker exec` 核对代码与产物，未触发真实采集。
